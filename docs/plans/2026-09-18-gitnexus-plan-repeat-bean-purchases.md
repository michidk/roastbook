## Objective (Section 1)

Make a rebuy a first-class child record of one stable coffee profile: users keep one bean page and cross-purchase brew history, while roast date, stock, price, shop, and shelf state stay accurate for each acquired bag.

## Proposed Changes (Section 6)

1. [verified] Keep descriptive fields, notes, and images on beans. Add bean_purchases with beanId, nullable purchasedAt, roastDate, initialWeightGrams, price, currency, shopUrl, isArchived, timestamps/checks, and unique (id, beanId). Add nullable brews.beanPurchaseId with a restricting composite FK; retain brews.beanId.
2. [verified] Generate one migration: one purchase per legacy bean, copy purchase fields/archive state, use bean IDs as deterministic initial purchase IDs, backfill brews.bean_purchase_id from brews.bean_id, advance the sequence, then remove purchase-only bean columns. Leave legacy purchasedAt null.
3. [verified] Refactor createBean to atomically create profile plus first purchase; make getBean/getBeanCollection return purchases and derive On shelf/Past from children. Add thin validated purchase functions backed by a focused .server.ts domain module.
4. [verified] Split BeanFields/form values into profile and purchase inputs. Keep /beans/$beanId as the profile, add "Add another bag," show active/past purchases with per-purchase remaining weight, and render one card per coffee with accurate coffee/bag counts.
5. [verified] Make NewShotForm/payloads/suggestions select an active purchase labelled by coffee, roast date, and remaining weight; derive beanId from purchaseId server-side. Recipes retain beanId and resolve an active purchase when loaded.
6. [verified] Keep brew lists/history/top-bean stats grouped by beanId. Join bean_purchases only for stock, roast age, cost, and selected-purchase AI evidence; recommendation history spans purchases.
7. [verified] Replace destructive history loss with dependency-aware deletion: referenced profiles/purchases move to Past and cannot be deleted; only unreferenced rows may be removed. Update demo, README, and DESIGN.

## Implementation Sequence (Section 7)

1. Reconcile dirty schema/UI work; implement relations and generate/review the backfill migration. Assert counts, mapping, sequence reset, and FK behavior before dropping old columns.
2. Add purchase validation/domain operations and update bean boundaries; keep profile plus first purchase atomic and compatible with image-upload recovery.
3. Implement split forms, grouped collection/detail, and Add another bag with typed URLs, invalidation, focus, empty/error states, and coarse-pointer targets.
4. Wire purchase selection through brew create/edit/defaults/suggestions while preserving stable bean grouping and recipe semantics.
5. Update stock, stats, recommendation evidence, demo, command/dashboard counts, docs, and bag/on-shelf/Past copy.
6. Add tests, run the migration with isolated PostgreSQL/S3, then browser-check 375px, 768px, and 1280px plus console/network failures.

## Test Strategy (Section 8)

- Migration: every legacy bean gets exactly one purchase; fields/archive/brew attribution survive; sequence and FKs accept valid inserts and reject mismatches.
- Domain/UI: two purchases under one profile, independent stock/archive state, explicit rebuy, multi-active selection, recipe fallback, and blocked destructive deletion.
- Analytics/AI: stable totals aggregate; linked purchase drives cost/roast age/current evidence; recommendation history spans purchases.
- Run package.json:27-34 commands in Section 11 plus responsive checks for collection, detail, rebuy, and new/edit brew.

- Migration loses no bean, brew, recipe, cafe-visit, media, or archive attribution; mismatches and destructive referenced deletes are rejected.
- Unit/integration/check/typecheck/build/verify and responsive browser checks pass; README and DESIGN describe shipped behavior.
